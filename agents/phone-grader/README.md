# PhoneGrader (macOS)

Native SwiftUI app combining `ORGRGNRK/phone-grader-bot` and `ORGRGNRK/resale-op-mcp`.

- `Sources/PhoneGraderCore` — pure-Foundation ports: `PriceEngine` (price-mcp `get_atlas_floor`,
  model-name resolution, real quotes, ladder status), `ListingCopyGenerator` (copy-mcp),
  `ListingPipeline` (listing-pipeline.js `evaluatePhoneAssessment`), `Grader` (grader.js schema/prompt),
  `DealRule` (max buy = floor − gas − repair parts − profit target — see below), `PhoneFacts` (buyer-facing facts).
- `Sources/PhoneGrader` — the app (Rig / Grade / Price / Comps / Listing / History / Parts / Settings).
- `Resources/` — `rubric.md`, `atlas-ladder.json`, `actual-quotes.json` copied verbatim from the repos.
- `Tests/` — XCTest ports of test_price.py, test_model_names.py, test_copy.py, listing-pipeline.test.js,
  plus golden parity fixtures generated by running the original Python servers (~8,700 cases).

Build: `./build.sh` (runs `swift test`, then xcodebuild → `dist/PhoneGrader.app`, ad-hoc signed).
Data: `~/Library/Application Support/PhoneGrader/` (history.json, photos/, imported ladder, buyer quotes).
Secrets: Keychain service `com.orgrgnrk.PhoneGrader` only.

## Max buy (Price tab / `pgctl price`)

One formula, profit subtracted once (the old $6 driving cost and $35/$50 buffers are gone):

    max buy    = Atlas floor (or a buyer quote) − gas − repair parts − profit target
    gas        = round-trip miles ÷ MPG × $/gal
    walk-away  = floor − gas − parts            (break-even)

- **Profit target** $40, **MPG** 24, **default round trip** 20 mi — Settings → Max buy; miles are editable per deal.
- **Gas price**: EIA weekly California regular (series EMM_EPMR_PTE_SCA_DPG), read from EIA's public history
  page (the JSON API needs a key). Falls back to the last EIA value, then a manual $/gal in Settings
  ($4.80 placeholder). Per-deal override on the Price tab; `pgctl gas [--refresh]` shows the source and week.
- **Repair parts**: back glass none / aftermarket / Apple, screen none / OEM / aftermarket. Costs in Settings are
  placeholders until you set them. Rear glass FAIL on the checklist pre-selects aftermarket back glass.
  Aftermarket back glass adds "Back glass replaced with aftermarket part" to the listing and receipt.
- **Parts log** (Parts tab): purchases with date / item / supplier / cost / optional phone link, running and
  monthly totals, Amazon Business CSV import (Order Date, Title, Item Net Total) with a preview. Parts linked to a
  phone replace the placeholder parts cost in that phone's max buy.
- With an asking price: BUY (≤ max buy) · THIN (≤ walk-away) · PASS (above walk-away), plus what you make at the floor.
- Example: floor $540, 20 mi, 24 MPG, $6.104/gal, no repairs → $540 − $5.09 − $0 − $40 = **$494.91**.
- All of these numbers live in UserDefaults with every other setting (keys in `DealSettings.swift`).
  History records save the full breakdown; QR receipts never contain floors, costs, max buy or profit.

## Buyer-facing facts: one source (`PhoneFacts`)

Listing text, the QR receipt's fact lines and the share photo are all built by `PhoneFacts` from the saved
History record: model, storage, unlocked, battery % and cycles, IMEI clean, iCloud off, condition in plain
words (no letter grade), and disclosures (aftermarket back glass, non-original screen, battery under 80%,
bad IMEI / activation lock). The receipt adds the private-but-shareable extras (grade, other checklist
items, SICKW order, serial) without repeating those facts.

History → a record → **Share**: *Save listing photo* (1080×1080 PNG, big facts, small facts-only QR in a
corner, optional IMEI hiding, no grade, no prices), *Copy listing text*, *Print receipt*.
Terminal: `pgctl share N --png PATH [--mask-imei]`, `pgctl receipt N`.

## CLI (`pgctl`)

The app binary doubles as a command-line tool: `PhoneGrader --cli <command>`. `~/.local/bin/pgctl` is a
two-line wrapper around the installed app. It runs the same AppState / RigSession / HistoryStore code
headless, so it uses the same settings, Keychain items and `history.json` as the window. Run `pgctl help`.

    pgctl status
    pgctl device                                   # read the USB-connected phone
    pgctl grade --model "iPhone 13 Pro" --storage 256 --photo a.jpg --photo b.jpg --check icloud=pass --check battery=88
    pgctl price --id 1 --save                      # Atlas floor + max buy
    pgctl listing --id 1 --ask 420
    pgctl rig run ~/frames/spin-01 --check icloud=pass --check imei=pass
    pgctl history show 1
    pgctl gradeLog send 1 --yes                    # configure Settings → Postgres / NocoDB first

Notes: `--backend` applies to that run only. A manual `--grade` isn't stored on the record (the app
doesn't store it either), so pass it again when you re-price a record that has no AI grade. Rig blockers
only last for one run, so `rig run` prices the phone at the end of the same run. The app's History tab
re-reads `history.json` when it's opened, and both processes reload before they write.

## Comps & suggested resale range (Comps tab / `pgctl comps`, `pgctl price --range`, `pgctl listing --template`)

- **Atlas buyback is the floor.** The suggested local range never goes below floor + margin (default $40).
- Comps: Swappa public pages only (listings, price guide, recent-sales sampling), ≥2 s between requests,
  cached 24 h in `~/Library/Application Support/PhoneGrader/comps-cache/`. Marketplace/OfferUp are **never
  fetched** — paste/type the asks you see (`pgctl comps --asks "640, 675, $699" --asks-source offerup`);
  they're stored in `local-asks.json`. A failed fetch shows "NO COMPS"; numbers are never invented.
- Range: low = max(floor + margin, anchor − discount) where anchor = local-ask p25 → else Swappa sold avg →
  else Swappa listing p25; high = local median ask → else Swappa sold median. Rounded to $5.
  Settings: `rangeMarginOverFloor`, `rangeDiscount`, `compsZip`, `compsCity`, `compsRadiusMiles` (pgctl config).
- Listing template is copy-only and never includes Atlas/buyback numbers.

## iPhone / iPad app

Open **`iOS/PhoneGraderiOS.xcodeproj`** in Xcode, scheme **PhoneGraderiOS**, pick your iPhone (or iPad / a simulator), press **Run**.
Signing: automatic, your free Personal Team (same team as LifeRPG), bundle id `com.christopher.phonegrader`.
A free-team install expires after about 7 days; press Run again with the phone connected to renew it (data stays).

How it's built: one codebase. `PhoneGraderCore` is the local Swift package product; the app target compiles the same
SwiftUI files in `Sources/PhoneGrader`, with Mac-only code behind `#if os(macOS)`. The project is generated from
`iOS/project.yml` with XcodeGen (`brew install xcodegen; cd iOS; xcodegen generate`) — only needed if you edit the yml.
The Mac app is unchanged: `./build.sh` / `swift test` work as before.

Works on iPhone/iPad: Grade (checklist, photos from camera / library / Files, AI grading, SICKW Check IMEI), Price & max buy
(bundled Atlas ladder + import a newer price list), Comps, Listing copy/titles, History with sale tracking, Share → listing photo,
QR receipt (share or print; Hide IMEI toggle), Parts log (+ Amazon CSV import), Rig (browser-fed camera slots / recorded folder), Settings.
Keys (SICKW, Anthropic, grade-log service) are entered in Settings and stored in the device Keychain.
Ollama / OpenAI-compatible base URLs are editable — use your server's Tailscale address (127.0.0.1 is the phone itself).

Mac only: USB "Plug in phone" reader (needs libimobiledevice / adb via Process), `--cli` / pgctl and `mcp/`, the claude CLI backend,
Rig watch-folder polling.

Moving data: Settings → Data. Export history.json on one device (AirDrop / Files), Import (merge) on the other. Same JSON as
`~/Library/Application Support/PhoneGrader/history.json`; a backup is written before each import; photos aren't included.
"Export price list in use" / "Import price list" moves the Atlas ladder the same way.

## PostgreSQL / NocoDB grade log

Airtable sending has been removed. Manual, opt-in logging now targets a private HTTPS
gateway backed by PostgreSQL, with NocoDB as the database frontend. See
[deployment and verification](Support/grade-log-setup.md). The SQL and gateway are
in this repository; deployment to Alexus and a row in the existing NocoDB base
remain unverified until authenticated access is available.

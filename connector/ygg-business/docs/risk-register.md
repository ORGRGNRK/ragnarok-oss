# Risk register — ygg-mcp-business (scratch pilot)

Status as of 2026-10-28. "Gap" = a known deviation from the intended design.

| # | Risk / gap | Likelihood | Impact | Mitigation now | Next step |
|---|---|---|---|---|---|
| R1 | **GAP: pgvector is not installed** in the scratch Postgres (`pg_available_extensions` has no `vector`). Vectors are stored as `real[]` in `mcp.search_vectors`, and every search loads all of them and ranks by cosine in the Node process. | certain | Search cost grows linearly with row count. Fine for ~92 rows, slow at tens of thousands. | Storage is isolated in `src/core/search/vector-index.ts`. Table shape `(item_id, model)` maps 1:1 to a pgvector column. | Install pgvector in the per-project Postgres, add `embedding vector(768)` plus an HNSW index, and switch `rank()` to `ORDER BY embedding <=> $1`. |
| R2 | **No Ollama on this Mac.** `nomic-embed-text` has never been exercised end to end. Only the stub embedder (tests) and a fake local HTTP server (unit test of the `/api/embeddings` client) have run. | certain | Search returns `upstream_unavailable` (retry-safe) until an embedder is configured. Real-model behaviour (dimension 768, latency, prefixes) is unverified. | URL and model are config. The client adds nomic `search_document:` / `search_query:` prefixes. Errors are actionable. | Point `BUSINESS_EMBEDDER_URL` at an approved local Ollama with `nomic-embed-text` pulled. Run one search and check `index.embedded_now` = row count. |
| R3 | **PII in Business data**: IMEI/IMEI2, lead contacts, buyer contacts, free-text notes. | high | Leaking identifiers to a model or log. | `business_get_item` returns IMEI last-4 only. IMEIs are excluded from the embedded text, so they never go to the embedder. Receipts store redacted args only. Lead/exit contacts ARE returned by the list tools (operator's own data). | Decide whether contacts should be masked by default, and add a role-level view that drops IMEI columns. |
| R4 | Deleted Business rows leave stale vectors. | low | Wasted storage only: search drops ids that no longer exist before returning. | Search filters by live rows. | Periodic prune: `delete from mcp.search_vectors v where not exists (...)`. |
| R5 | Incremental indexing trusts `updated_at`. A row edited without bumping `updated_at` is not re-embedded. NocoDB does bump it. | low | Stale search text for that row. | Content hash skips re-embedding unchanged rows. A full re-scan is one `delete from mcp.index_state where model = ...`. | Optional nightly re-scan. |
| R6 | `index_state` is keyed by model only: one indexed source per database per model. | low (one source today) | A second indexed table in the same DB would share the position. | Documented. | Add a `source` column before indexing a second table. |
| R7 | First search after many changes embeds them all inside one call (sequential HTTP calls). | medium | Slow first call. Can hit `BUSINESS_SEARCH_TIMEOUT_MS`. | Batches commit progress, so a timed-out sync resumes where it stopped. Retry is safe. | Warm the index after imports, or batch with `/api/embed`. |
| R8 | The rate limiter is per process, not global. | low (single bot owner) | Several server processes multiply the allowed rate. | One MCP per project, owned by one bot. | Move to a DB-backed limiter if more clients appear. |
| R9 | Receipt writes are best-effort. If `mcp` is missing or ygg_app is down, tools still answer but no receipt is stored (logged to stderr). | low | Audit gap. | stderr log line `receipt write failed`. | Alert on that log line, or fail closed if audit becomes mandatory. |
| R10 | No `outputSchema` declared. Output shapes are documented and tested, not schema-enforced by clients. | medium | Clients cannot validate results automatically. | Shapes are fixed in code and asserted in tests. | Add an `outputSchema` per tool once the shapes settle. |
| R11 | Owner role `ygg_app` can technically write `public` tables. The server only issues writes to `mcp.*` (code review plus a checksum check of `public."Business"` before and after). | low | Accidental data change if code regresses. | Writes are confined to `PgReceiptWriter` and `VectorIndex`, and both hardcode schema `mcp`. Reads use `ygg_read` in read-only sessions. | Create a dedicated `ygg_mcp` role that owns only schema `mcp`. |
| R12 | Scratch-only verification. Nothing ran against the live Yggdrasil or Alexus. | certain | Production differences (data volume, grants, network) are untested. | Config is env-only, and nothing is hardcoded to scratch except `scripts/scratch-env.sh`. | Operator-run rehearsal against the real per-project DB. |
| R13 | Money values are converted from `numeric` to JS numbers. | low | Float rounding beyond 2 decimals on large sums. | Totals are rounded to cents. | Return strings if sums ever exceed 2^53 cents. |
